# Video Ads投广工具

读取 Excel `.xlsx`（第一个工作表）或 CSV，提取 `Video Link` 中的视频代码，与 Shopee Seller App 中逐条遍历的视频比对。目标视频按表格参数发布广告，非目标直接继续。保留所有 Excel 行；历史遍历记录按 Copy Link 去重，识别及投广结果可导出 CSV。

## 使用

1. 启动 Android 模拟器，登录 Shopee Seller。
2. 在此目录运行 `python3 app.py`，保持服务运行。
3. 打开 [视频识别网页](http://127.0.0.1:8765/)。不要双击 `index.html`。
4. 上传文件。表头需要包含 `Video ID`、`Video Link`、`Duration`、`Daily budget`、`Objective`。
5. 在“目标视频列表”Tab 勾选本轮要匹配和投广的视频，可逐行选择或全选；核对 Duration、Daily budget、Objective 后，点击“开始识别并投广”。流程从 Seller Home → Shopee Video 的第一个视频开始，只把勾选的视频作为本轮目标。

### GitHub Pages 与模拟器

GitHub Pages 地址 `https://sherryshen2.github.io/Auto-Video-Ads-Tool/` 只能展示静态网页，不能运行本项目的 Python `app.py`。上传 Excel 和控制模拟器依赖本机的 `/api/*` 接口；直接在 Pages 页面上传时，接口可能返回 HTML 错误页，浏览器因而显示 `Unexpected token '<' ... is not valid JSON`。请在**运行模拟器的同一台 Mac**上启动 `python3 app.py`，用 [本机工具地址](http://127.0.0.1:8765/) 上传文件和操作模拟器。

模拟器通过 Android Debug Bridge (ADB) 与本机服务连接，无需把模拟器连接到 GitHub。可在终端运行 `~/Library/Android/sdk/platform-tools/adb devices`，看到 `emulator-5554 device` 等设备记录后，再刷新本机工具地址；网页右上角会显示模拟器连接状态。若使用另一台电脑打开 GitHub Pages，该电脑的 `127.0.0.1` 指向它自己，无法调用这台 Mac 上的模拟器。

“系统遍历记录”在独立 Tab 中展示，仍记录本轮遍历到的所有视频。未勾选的 Excel 行一直保留在目标视频列表中，但不参与本轮匹配或投广。默认勾选所有可解析 Video Link 的行；没有勾选可识别视频时无法启动。任务运行中不能修改勾选状态。

Shopee 当前页面提示：**发布 GMV Max 会停止其他正在投放的视频广告**。本轮勾选的视频包含 GMV Max 时，网页会显示这一提示。

每个视频自动执行：

1. 优先点击 More，找不到时尝试视频右侧同位置的 Promote。点击后等待 5 秒，再查找并点击 Copy Link；等待结束后仍有 2.5 秒的按钮查找重试时间。
2. 读取模拟器刚复制的 Shopee 链接，校验复制时间，避免拿到上一条链接。先按 Copy Link 查询历史：已有完成结果就复用视频代码、跳过浏览器识别；已有异常结果则在原行重试、覆盖结果，不新增重复链接。
3. 在电脑 Google Chrome 的专用普通窗口（900 × 680）中打开链接；不使用最大化窗口，不反复切换 Chrome 到前台。
4. 从打开链接开始，最多等待 100 秒，待页面加载结束且地址稳定后读取最终地址，随即关闭本次专用窗口。每次地址读取也受剩余等待时长限制。读取失败、跳转超时、标签页丢失、解析失败或用户停止时也执行关闭；关闭失败最多重试 3 次，保留窗口编号供后续清理，不继续累积新窗口。窗口创建及关闭重试不计入地址提取的 100 秒。
5. 从最终地址的 `/share-video/` 路径提取代码，去掉末尾 `=`，与 Excel 逐行比对。
6. 如果是本轮勾选的目标视频，立即在当前视频执行下方全部投广步骤：选择参数、Publish、读取弹窗、保存结果、回退；这些步骤结束后才滑动并开始识别下一条。复用历史识别结果的目标也遵循相同顺序。非目标直接继续。单条读取失败时保留错误原因，先标记“读取失败，待跳过”；如有分享菜单，先关闭菜单，再执行滑动，完成切换动作后标记“读取失败，已跳过”。

只有浏览器实际返回的分享视频地址参与比对；历史完成结果可直接复用。本轮勾选的目标全部识别且投广逐条处理完成后，返回 Seller APP 主页并结束。若这些视频已有识别记录且投广结果为成功，仍会进入 Seller 视频列表重新投广；待审核或结果待确认的提交暂不重复发布。重复的选中代码由同一个视频匹配。

## 目标视频投广

1. 在当前视频重新点击 More 或右侧同位置的 Promote，等待 5 秒并确认分享菜单已打开；再单独点击菜单左下方、Copy Link 左侧的橙色 Promote。确认看到 `Create Video Ads` 后才填写参数。界面读取暂时为空时等待重试，两个入口步骤各最多等待 30 秒；菜单内 Promote 点击后仅等待页面加载。进度和失败原因分别记录到具体步骤。
2. Duration 支持正整数天数或 `No End Date`。预设选项直接选择；其他天数通过 `Customise Duration` 滚轮选择并读取当前值，再点 Next。
3. Daily budget 按表格金额填写：预设金额直接选择，其他金额通过 `Customise Daily Budget` 聚焦并清空输入框，确认清空后逐字输入金额（例如 RM5.00 输入 `5`）。每次回读重新获取界面，连续两次金额一致后点击 Next，再核对表单中实际选中的金额。金额迟迟不匹配会清空重试一次，整个预算步骤最多等待 60 秒；记录预期金额和实际读值。金额格式 `5`、`5.0`、`5.00` 等价。当前 App 提示范围为 RM1～RM10b；最多两位小数。不会替用户上调或下调预算。
4. Objective 使用当前页面选项 `GMV Max` 或 `Boost Views`。
5. 发布前再次确认三项实际选中值。Seller 的按钮没有暴露 accessibility selected 状态，辅助程序使用控件 ID、文字和值，并检查按钮实际的橙色选中边框；任何一项无法确认时记录失败，不点击 Publish。
6. 持久保存本次提交标记，再仅点击一次 Publish。在点击后 9 秒内读取控件、独立窗口和提示事件，同时连续截图捕捉短暂弹窗。使用 macOS Vision 在本机识别截图文字，并与发布前画面对比，排除页面原有文案。弹窗出现 `Done`、`successfully`、`success` 或明确发布成功提示时标记“发布成功”；`not enough`、`insufficient`、`failed` 等明确失败提示标记“发布失败”。失败提示优先于 `Done` 关闭按钮。例如 `Wallet balance is not enough to run ads. Please top up to RM20.00` 会标记失败并展示原文。仅有审核提示时标记“已提交审核”；无可确认提示时标记“结果待确认”。
7. 无论结果如何均回退到视频页，尚有目标需要处理时再滑动下一条。若退到了视频列表，沿用卡片定位恢复下一条。全部目标处理完或列表遍历到底时，继续点击返回，看到底部 Home 导航后进入 APP 主页。网页先显示“正在返回主页”，随后显示返回结果；回退异常单独记录，识别和投广结果保留。投广失败不会把识别结果改成识别失败。

同一视频代码默认在一轮中只处理一次投广；即使 Copy Link 不同也不重复提交。每次重新开始时，已成功且本轮勾选的视频会重新走投广流程；待审核或提交结果不明的视频仍暂不重复 Publish。明确失败的记录可以在下次运行时重新尝试。同一视频在选中行中存在不同投广参数时，记录参数冲突并继续，不任意选择其中一组。投广参数或页面布局不受支持时同样记录原因并继续。

### 手动确认投广结果

Excel 清单和系统遍历记录中的“结果待确认”下方提供“标记成功”和“标记失败”：

- 标记成功：保存为“发布成功”；本轮后续遇到同一视频不重复投广，下一轮若再次勾选则重新投广。
- 标记失败：保存为“发布失败”，再次遇到该目标视频时重新执行完整投广流程。运行中确认其他视频失败后，本轮后续再次遇到它也可以重试；若已经遍历结束，点击“开始识别并投广”后重试。
- 当前视频仍在投广或返回视频页时，确认按钮暂不可用；该视频处理结束后即可选择。未人工确认的未知结果继续保留，避免自动重复提交。
- 人工选择保存到本地投广凭据，Excel 清单、同一代码的所有遍历记录和结果统计同步更新。刷新、服务重启、清空识别历史均不会丢失已保存的选择。
- 保留原自动判定、弹窗原文及人工确认时间；重新投广时增加尝试次数并保留之前的投广记录。确认操作只更新记录，投广仍在遍历到目标视频时执行。

如果还有目标未匹配，会继续滑动。再次读取到已遍历的链接时，才返回视频列表，按卡片序号确认下一条是否存在；连续 3 条连原始链接都无法读取时，也从最近确认的位置改用卡片定位，直到重新取得链接。末尾判断需要当前没有下一张卡片、原生列表拒绝继续向下滚动，并且连续 4 秒没有加载或列表变化；仅遇到重复的视频代码不会提前结束。结束时页面显示“目标全部找到”或“列表已遍历到底”，并保留未匹配项和失败记录。可以随时点击“停止识别”。

## 失败与继续

- 复制、读取剪贴板、浏览器跳转或提取代码出错时，自动跳过当前视频，不等待手动确认。原始链接、已取得的浏览器地址和错误原因均保留。
- 网页单独显示“已跳过”数量，跳过的视频不计入“非目标”。
- 识别阶段 More / Promote 用于获取 Copy Link；只有代码匹配到当前 Excel 的视频才进入投广表单。
- 单条读取失败后会实际执行滑动，不再每条都先返回视频列表。若切换命令或列表恢复失败，会自动重试 2 次；仍无法操作模拟器时才提示恢复后“继续下一条”，继续定位同一张待处理卡片。
- 若 Chrome 授权被 macOS 拒绝，请在“系统设置 → 隐私与安全性 → 自动化”允许启动服务的应用控制 Google Chrome。
- 工具先保存专用窗口和标签页 ID，再打开链接。读取标签页失败时仍保留窗口 ID，并在清理时关闭这个专用窗口；其他 Chrome 窗口不受影响。

## 保存与导出

- 页面显示全部 Excel 目标行和去重后的历史遍历记录，包括目标、非目标、失败、跳过和处理中。
- Copy Link 以去除首尾空白后的完整文本作为唯一键，不改写链接参数。相同代码但不同 Copy Link 仍分别保留，标注“同视频代码”。未取得 Copy Link 的失败记录无法确定视频身份，单独保留。
- “已完成”指已成功提取代码并完成比对的目标视频或非目标记录：再次遇到时不打开 Chrome、不新增记录、不修改原识别结果和时间，但未投广的目标仍进入投广流程。“本轮复用”统计本轮复用的识别结果数。
- 失败、中断、停止或未完成记录再次遇到同一链接时，在原记录上重新识别；保留原序号，增加尝试次数，用本次状态、地址和错误覆盖旧结果。服务恢复时也会合并旧的重复链接：优先保留首条成功记录，否则保留最近的异常记录。
- 上传新 Excel 或重新开始识别均保留现有历史。本轮匹配统计只计算勾选的视频；历史识别结果继续保留。只有“清空历史记录”会主动清除这些结果。
- 每条遍历包含原始 Copy Link、浏览器最终地址、视频代码、匹配的 Video ID / Excel 行、时间、尝试次数和错误原因，以及投广参数、状态、弹窗原文、Publish 时间、投广错误和回退错误。
- Excel 清单和系统遍历记录的“投广结果”列，在“发布失败”下方只展示一条失败原因，避免截图 OCR 的重复文字；完整弹窗与 OCR 证据仍保存在原始投广记录和导出 CSV 中。旧记录未保存原因时显示“未记录到具体失败原因”。
- Publish 前后截图与截图文字保存在 `.runtime/publish-popups/<本次操作编号>/`，识别结果记录文字来源。截图文字识别全部在本机完成。
- 历史记录同步保存到浏览器本地存储及 `.runtime/session.json`。每次运行另存 `.runtime/sessions/<run_id>.json` 快照，重新开始会继承当前历史，不覆盖旧运行快照。
- 刷新页面后会从本地服务恢复当前运行。服务重启会保留记录，但不会从未知的模拟器位置继续。
- 导出 CSV 同时包含所有 Excel 行和当前保留的去重历史记录，标明本轮是否勾选，并附加投广参数、结果、弹窗原文、人工确认结果及时间、原自动判定和历史投广尝试。
- “系统遍历记录”右侧的“清空历史记录”会清空识别历史和匹配统计，保留 Excel 清单及 `.runtime/promotions.json` 中的投广提交凭据。下次启动时，勾选的成功视频仍会重新投广；结果待确认和待审核的提交继续按凭据避免重复发布。识别运行或停止处理中不可清空；需要保留结果时可先导出 CSV。

## 本机依赖与实现

- macOS、Google Chrome、Python 3、Android SDK / Build Tools、Android Studio JDK、Xcode Command Line Tools（编译本机 Vision 文字识别程序）；模拟器 Android 13 或以上。
- `android/VideoButtons.java` 通过 ADB 运行，直接查找 More / Copy Link，不等待播放页空闲、不导出整页 XML。辅助进程设有超时退出，避免卡住后占用后续识别连接。
- `android/VideoPromotion.java` 处理投广表单、选项回读、单次 Publish、弹窗读取和返回；`promotion.py` 校验参数并在每个阶段保存投广状态。Publish 前会将提交标记写入磁盘，重启或中断后不会自动重试结果不明的提交。
- `popup_capture.py` 和 `native/PopupOCR.m` 读取 Publish 后的连续截图，补充无法通过控件树读到的短暂弹窗，不额外点击 Publish。
- `android/clipboard/` 是本项目的剪贴板辅助应用源码。首次识别自动编译并安装到模拟器，复制后短暂打开读取，再返回 Seller。无网络权限，不后台监听剪贴板；只返回本次复制时间之后的 Shopee URL。
- Android 剪贴板在应用有输入焦点时才能读取，因此使用前台辅助页面；以 `ClipDescription.getTimestamp()` 判断是否为当前复制操作。[Android ClipboardManager](https://developer.android.com/reference/android/content/ClipboardManager#getPrimaryClip())、[ClipDescription](https://developer.android.com/reference/android/content/ClipDescription#getTimestamp())。
- `browser_link.py` 使用 Chrome 提供的 macOS AppleScript 接口打开 URL、读取 URL 和加载状态。链接通过独立参数传入，不拼入脚本，不改动电脑剪贴板。
- 编译产物与运行记录保存在 `.runtime/`，已被 Git 忽略。

旧版 `.xls` 暂不支持。打开视频可能会被 Shopee 记录为浏览。
